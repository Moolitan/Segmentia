# SegKV 研究笔记:复用一段 KV 缓存,误差到底从哪来

## 这份文档怎么读

这是一份**从头讲起**的笔记,不假设你记得我们之前讨论的任何东西。每个名词第一次
出现时,我都会先用大白话解释一遍,再往下说。建议从上往下顺着读,不要跳。

一句话先交代结论,免得你读到一半不知道要去哪:

> 我们想把一段重复出现的文本(叫"skill")的中间计算结果缓存下来重复用,以省时间。
> 这会带来误差。误差可以分成两部分:一部分跟"这段文本被放在什么位置"有关,
> 另一部分跟"这段文本前面是什么内容"有关。**位置那部分我们已经用一个不需要重新
> 训练模型的小技巧解决了;内容那部分是真正的难点**,本文把它讲清楚,并给出我们
> 目前对"怎么修"的初步实验。

---

## 1. 背景:我们在做的事

现在的 AI agent(比如帮你写代码、写文档的助手)在一次任务里会反复用到一些固定的
"技能说明书"。比如一个叫 `internal-comms`(内部沟通)的技能,它的说明书是一大段
文字,告诉模型"写事故通报时要先说影响、再说状态……"。

在一次多轮对话里,这段说明书会**一字不差地出现很多次**(第一轮要写通报时出现一次,
第三轮再写时又出现一次,等等)。我们把它每次出现叫一个 occurrence,简写 occ:
第一次是 occ1,第二次是 occ2,以此类推。

**问题是**:模型每次看到这段说明书,都要从头把它"算"一遍,很费时间。既然文字一样,
能不能**算一次、存下来、后面直接拿来用**?这就是我们做的事,项目代号 SegKV。

要讲清楚"存什么、为什么会有误差",得先花一点篇幅说明白模型是怎么"读"文字的。
这部分是基础,后面全靠它,请耐心看。

---

## 2. 基础:模型是怎么"读"一段文字的

### 2.1 token

模型不是按字读,而是按 **token** 读。token 就是把文字切成的一小块(一个词、半个词
或一个标点)。一段说明书会被切成几百个 token。下面说"第几个 token"就是指这个。

### 2.2 层(layer)和"理解向量"

模型内部是一摞**层**,数据从第 0 层一路往上流到最后一层(我们主力用的 Qwen3-14B
有 40 层)。每经过一层,模型对每个 token 的"理解"就更深一点。

对**某一个 token**,它在**第 l 层**的"理解",我们用一个记号表示:`h_l`。

`h_l` 到底是什么?它就是一串数字(一个向量),代表"模型读到第 l 层时,对这个
token 当前的理解"。这串数字也常被叫做**激活值**(activation)。换句话说,
**`h_l` = 这个 token 在第 l 层的激活向量**。

举个具体例子。看句子"我坐在河边的**岸**",聚焦最后那个字"岸":

- 在**第 0 层**,`h_0`("岸")只是"岸"这个字本身的意思,各种意思(河岸?堤岸?)
  混在一起,因为这时模型**还没看前面的"河边"**。
- 越往上走,模型会回头看前面的"河""边",把信息吸进来。到了**很深的层**,
  `h_l`("岸")已经明确变成"水边的那块陆地"了。

所以记住一件事,它是后面一切的关键:

> **同一个字,放在不同的前文后面,它在深层的"理解向量"`h_l` 是不一样的。**
> "河边的岸"和"银行柜台的对岸",这个"岸"字在深层的 `h_l` 完全不同。

### 2.3 注意力:前文是怎么进到 `h_l` 里的

模型靠一个叫**注意力**(attention)的机制,让每个 token 去"看"它**前面的所有
token**,按相关程度把信息汇集到自己身上。这是前文影响一个 token 的**唯一通道**。
"岸"之所以在深层变成"河岸",就是因为它通过注意力看到了前面的"河"。

### 2.4 K 和 V:从"理解向量"里拿出来的两样东西

在每一层,模型会从这个 token 的理解向量 `h_l` 里,用两个固定的变换,各算出一个向量:

- **K(Key,可以理解成"标签")**:别的 token 用它来判断"要不要看我"。
- **V(Value,可以理解成"内容")**:一旦被别人看上,真正传出去的信息。

这里有个**贯穿全文的关键事实**:K 和 V 都是从**同一个** `h_l` 算出来的。所以
`h_l` 一变,K 和 V 都会跟着变。

### 2.5 KV 缓存:我们要复用的就是它

模型算完每个 token 每一层的 K 和 V 后,会把它们存起来(叫 **KV 缓存**),这样后面
的 token 做注意力时直接读,不用重算。

**SegKV 要做的,就是把 skill 这段文字的 K、V 缓存下来,下次它再出现时直接塞进去,
省掉重算。** 误差就出在"塞进去的 K/V"和"如果老老实实重算会得到的 K/V"不完全一样。

### 2.6 位置:模型怎么知道每个 token 在第几位

模型还需要知道每个 token 排在第几位。它用的办法叫 RoPE,简单说就是:**按 token
的位置,给它的 K 施加一个"旋转"**。这个细节在讲"位置问题"时会用到,先记住一句话:
**位置信息是通过对 K 旋转来表达的,V 不带位置。**

### 2.7 怎么衡量"复用得准不准":相似度打分

我们需要一个数,衡量"复用拿到的 K(或 V)"和"老实重算的 K(或 V)"有多像。
我们用**余弦相似度**:两个向量方向越一致,分数越接近 1;完全一样就是 1.0,
越不像分数越低。后文所有"0.9""0.5"这类数,都是这个相似度,**1.0 代表无损复用**。

好,基础讲完了。下面进入正题。

---

## 3. 我们要回答的问题,以及怎么拆

skill 缓存一次、后面复用,和"在新位置老实重算"相比,会有差距。这个差距来自两件
**不同**的事,我们一件一件查:

- **位置问题**:复用时,这段 skill 落在对话里更靠后的位置了(绝对位置变大)。
- **内容问题**:复用时,这段 skill **前面的对话内容**变了(occ1 前面是一段话,
  occ2 前面是另一段不同的话),而我们缓存的 K/V 是"当初对着旧前文算出来的"。

下面第 4 节讲位置,第 5 节讲内容。

---

## 4. 第一半:位置问题(已经解决)

### 4.1 我们的做法:把缓存的 K 重新旋转一下

前面 2.6 说过,位置是通过"旋转 K"来表达的。skill 缓存时是在旧位置算的,它的 K 带
着"旧位置的旋转"。复用到新位置时,我们就把这个旋转**重新拧到新位置**(代码里叫
re-rotation,在 `rope.py` 里)。注意:它**只动 K,不动 V**,因为 V 不带位置。

### 4.2 为什么这个旋转在数学上是准的

可以证明:只要这段 skill 的"理解向量" `h_l` 不变,把缓存的 K 重新旋转到新位置,
得到的**正好就是**"这段 K 本来就该在新位置长的样子",而且每一层都成立。换句话说:

> **位置这一半,旋转一下就精确补回来了,不需要重新训练模型。**

### 4.3 一个会不会翻车的担心:位置太靠后

旋转唯一可能出问题的地方,是新位置**超出了模型训练时见过的最大长度**(那时 RoPE
的行为会变得不稳)。我们查了实际数据:

- Qwen3-14B 训练时见过的最大长度是 40960。
- 我们的对话里,skill 复用时最靠后也就到第 24666 个 token,大约是上限的 60%。

所以都在安全范围内,**不会翻车**。

### 4.4 实测证据:旋转只补 K,完全不碰 V

我们的数据里正好有一个"**不做旋转**"的对照组。把 8 个案例平均一下:

| 做法 | K 的相似度 | V 的相似度 |
|---|---|---|
| 做了旋转 | 0.900 | 0.743 |
| 没做旋转 | 0.636 | 0.743 |

读这张表:

- 旋转把 K 的相似度从 0.636 提到 0.900——这就是它补回来的"位置那一半"。
- V 的相似度在两种情况下**几乎一模一样**(0.7432 和 0.7433)。这说明旋转根本碰不到
  V,因为 V 不带位置。

**这张表是整件事的关键证据**:它同时证明了"位置那一半能靠旋转补好",以及"V 的
误差和位置无关,纯粹是内容问题"。

### 4.5 小结

位置问题用一个不需要重新训练的旋转就解决了。剩下的所有误差(K 还差一点点,以及
V 差得比较多),都属于下一节的**内容问题**。

---

## 5. 第二半:内容问题(真正的难点)

### 5.1 误差是怎么来的

回到 2.2 那个"岸"的例子。skill 这段文字每次出现都是同样的字,但前面的对话不同。
于是 skill 里每个 token 在做注意力时,看到的前文不一样,它的"理解向量" `h_l` 就
不一样,从 `h_l` 算出来的 K、V 自然也不一样。这就是误差的根源。

而且这个误差**越深越大**,原因也顺理成章:

- 在第 0 层,token 还没看前文(只认字),所以不管前面是什么,K、V 都一样,
  相似度是 1.0。
- 每往上一层,就多吸收一次"对不同前文的注意力",误差一层层累积,所以**最深的层
  误差最大**。

### 5.2 最重要的发现:V 比 K 差得多

我们直接量了每一层 K 和 V 的相似度(代码见 `kv_drift_analysis.py`)。两个差别很大的
案例(一个 skill 71 个 token,一个 3313 个 token)结论一致。挑几层看:

| 层 | K 相似度 | V 相似度 |
|---|---|---|
| 第 0 层 | 1.000 | 1.000 |
| 第 15 层 | 0.928 | 0.776 |
| 第 20 层 | 0.826 | 0.489 |
| 第 39 层(最深) | 0.908 | 0.515 |

可以看到:到了深层,**K 还有 0.8~0.9,V 却掉到了 0.5 左右**。0.5 意味着复用的 V 和
真实的 V 已经差出去快 90 度,基本不能用了。

### 5.3 为什么 K 抗造、V 不抗造

我们进一步看了 K 和 V 的内部构成,发现一个清楚的物理原因:

- **K 里面有几个数特别大,而且基本不随前文变**(我们测到,某一个维度就能占 K 全部
  "能量"的大半)。这几个又大又稳的数,把 K 的相似度"撑住"了。
- **V 没有这种又大又稳的数**,它的内容平摊在各处,而且都跟着前文变。前文一变,V 就
  整体跟着变,所以相似度掉得厉害。

用一句话概括这个发现(这是我们最有价值的结论):

> **K 像是"标签/索引"——我是谁,这件事跨前文比较稳定,所以可以复用。**
> **V 像是"按前文加工出来的内容"——前文一变它就变,所以不能直接复用。**

这一点很重要,因为最接近我们的竞品工作(一篇叫 CacheSlide 的论文)声称"V 的相似度
会跟着 K 一起好"。而我们的数据显示,在深层 **K 和 V 严重分家**(K 0.9,V 0.5),
并且在两个差别很大的案例上都成立。这是我们能站得住、并且和别人不一样的发现。

### 5.4 一个绕不开的难题(它决定了下一步)

既然 V 在深层不能用,自然的想法是"那就重算 V 嘛"。但这里有个绕不开的坎:

回忆 2.4——**K 和 V 是从同一个理解向量 `h_l` 算出来的**。所以:

- 想要正确的 V,就必须先有正确的 `h_l`;
- 而要算出正确的 `h_l`,就得做那一层昂贵的注意力计算;
- 一旦 `h_l` 算出来了,顺手算 K 几乎不要钱。

也就是说,**"只重算 V、省下 K"根本省不了多少计算**。要省计算,只能从"少算几个
`h_l`"下手。怎么少算?这就是下一节的实验。

---

## 6. 怎么修,又能省计算?(初步实验)

### 6.1 想法:存一个"中间存档",从中间接着算

第 5.4 节说过,"只重算 V"这条路走不通,因为正确的 V 依赖正确的 `h_l`。那真正
能省计算的方向就只剩一个:

> **除了缓存 K/V,还要额外缓存 skill 在某个中间层 N 的残差流激活 `h_N`。**

这里的 `h_N` 可以理解成"模型读到第 N 层时,对 skill 每个 token 的中间理解"。
如果以后同一段 skill 又出现,我们希望能跳过 skill 的前 N 层计算,直接从这个
`h_N` 往后接着跑。

更具体地说,第一次看到 `P1 + skill` 时,我们存下两样东西:

- skill 的浅层 KV;
- skill 在第 N 层输入处的激活 `h_N`。

第二次看到 `P2 + skill` 时,我们想这么做:

- 对真实的新前文 `P2` 正常计算;
- 对 skill 的前 `0..N-1` 层不再重算,而是在第 N 层输入处把 skill 对应位置替换成
  上次缓存的 `h_N`;
- 从第 N 层到最后一层继续正常跑,并且让 skill 的注意力能看见真实的 `P2`。

如果这个办法成立,就能省掉 skill 在前 N 层的计算。N 越大,跳过的层越多,理论上
省得越多。

### 6.2 根本疑问:错的 `h_N` 能不能被深层纠正

上面这个想法有一个很大的风险:缓存的 `h_N` 是在旧前文 `P1` 后面算出来的,不是在
真实新前文 `P2` 后面算出来的。也就是说,我们注入的是一个**带着旧前文影子**的
中间激活。

把两条路径写出来会更清楚:

```text
正确路径: h_0 -> h_1 -> ... -> h_N(在 P2 下正确计算) -> ... -> h_L
注入路径: h_0 -> h_1 -> ... -> h_N(从 P1 缓存拿来)   -> ... -> h_L
```

从第 N 层往后,模型确实能通过注意力看到真实的 `P2`;但第 N 层输入本身已经错了。
所以 Step 3 要回答的核心问题就是:

> **深层继续计算时,能不能利用真实的 `P2` 上下文,把这个错的 `h_N` 逐渐拉回到
> 接近完整重算的结果?**

如果能拉回来,说明"残差流 checkpoint + 深层 resume"这条路可行。如果拉不回来,
那错误的 `h_N` 会一路传下去,最后还是和直接复用差不多。

### 6.3 实验设计:三条路径对比

我们用一个小模型(Qwen3-1.7B,28 层)直接测了这件事(代码见
`residual_checkpoint_probe.py`,这个实验不需要启动 vLLM)。实验构造两段不同前文:

- `P1`:旧前文,也就是缓存产生时的上下文;
- `P2`:新前文,也就是这次真正应该回答的上下文;
- `skill`:固定不变的技能说明书。

然后比较三条路径:

| 路径 | 含义 | 用来回答什么 |
|---|---|---|
| `truth` | `P2 + skill` 完整重算 | 标准答案 |
| `reuse` | 直接拿 `P1 + skill` 的结果来用 | 纯复用会错到什么程度 |
| `resume@N` | 在 `P2 + skill` 的第 N 层输入处,把 skill 的 `h_N` 替换成 P1 缓存 | 待验证方案能不能把错误纠正回来 |

最后不看文本输出,而是看深层 V 向量和 `truth` 的余弦相似度。判定标准很简单:

- 如果 `resume@N` 接近 `truth`,说明深层能纠正错误的 `h_N`,方案可行;
- 如果 `resume@N` 接近 `reuse`,说明错误没有被纠正,方案不可行。

N 可以取不同值,比如 2、4、6、8、12、16。N 越大,跳过的前层越多,但注入的
`h_N` 也越深、越带旧前文的信息,因此越难纠正。

### 6.4 实验结果

结果如下(N 越小=存档越靠浅=省的计算越少):

| 做法 | 省下的层 | 深层 V 相似度(最后一层) | 把"复用到正确"的差距补回了多少 |
|---|---|---|---|
| 直接复用 | 0% | 0.912 | —— |
| 从第 2 层接着算 | 7% | 0.998 | 96% |
| 从第 6 层接着算 | 21% | 0.991 | 79% |
| 从第 8 层接着算 | 29% | 0.982 | 67% |
| 从第 12 层接着算 | 43% | 0.968 | 43% |

**好消息**:这个想法是成立的。从中间存档接着算、让深层看真实前文,**确实能把深层
V 拉回接近正确**,而且存档越靠浅,补得越好。这条路和别人常用的做法不一样,而且
不需要重新训练模型。

### 6.5 三个必须老实说的问题

1. **一个反直觉的限制**:误差在深层,要修它就得重算大部分层,所以"按层省计算"的
   上限其实很低——想补得好(80% 以上),存档就得放很浅,也就只能省掉前 15~30% 的
   层。这说明光靠"按层深"省不了太多。

2. **这个小模型、这个例子,本身误差就没那么大**(V 相似度 0.85~0.95),不像 14B
   真实对话里掉到 0.5。所以上面的"补回多少"是在一个较小的差距上算的,**还需要在
   14B 的真实大差距场景里再跑一遍确认**。

3. 这个实验为了公平对比,把浅层也算了再丢掉,所以它证明的是"结果对不对",**不是
   直接的加速比**。

### 6.6 由此引出的设计方向

把 6.5 第 1 点想透,会得到一个更可能对的方向:既然误差既集中在"深层",也集中在
"一部分 token"(不是每个 token 都漂),那最划算的做法可能是**两个维度一起挑**:

> 只重算"真正漂得厉害的那些 token",而且"只从某个深度开始算"。

这就把"按 token 挑"(别人常用)和"按层深挑"(我们新发现)结合起来,由我们的
测量结果来决定挑哪些。这是下一步要验证的设计。

## 7. 现在到哪了,还没决定什么

已经搞清楚的:

1. **位置问题**:用不需训练的旋转解决了,位置不是瓶颈。
2. **内容问题**:误差源于深层看了不同前文;**V 比 K 差得多**(深层 V 约 0.5),
   原因是 K 是稳定的"标签"、V 是随前文变的"内容"。这是我们的核心发现,
   和竞品 CacheSlide 的说法相反。
3. **怎么修**:"从中间存档接着算"能把深层 V 拉回正确,机制成立;但光按层深省不了
   太多计算,真正的设计大概率是"按 token + 按层深"两个维度一起挑。

  是不是真的比别人只按 token 挑更好。
- **C**:先把以上整理成一页提案,再决定投入多少。

  - 运行:`python replay/residual_checkpoint_probe.py`
