# Final Design Doc — Automatic Retry for Failed Benchmark Tasks

## Audience and length  
Teammates working on agent infrastructure. Target: ~1.5 pages.

## Problem  
Manual reruns of transient failures are costly and error-prone. Three common failure shapes exist:  
- Web retrieval timeout (manual rerun → success)  
- Transient I/O error (manual rerun → success)  
- Logic bug (manual rerun → still fails)  

## Solution  
Add bounded retry with classification:  
- **Classifier rules** (explicitly enumerated):  
  - `retryable_transient`: HTTP 5xx errors, timeout exceptions, DNS resolution failures  
  - `retryable_with_caution`: Rate-limit headers, "try-after" signals  
  - `non_retryable`: Logic errors, assertion failures, deterministic crashes  

- **Retry policy**:  
  - Max 3 retries for `retryable_transient`, 1 for `retryable_with_caution`  
  - Exponential backoff: 30s → 60s → 120s → 5min max  
  - Logs: `retry_of`, `attempt_number`, `failure_class`, `delay_before_attempt`, `final_status_after_retries`  

- **Persistence**: Retry state stored in shared DB; worker restarts do not interrupt retries.  

- **Dashboard signal**: "Retried 3 times before final failure" appears in task detail view.  

## Rollout  
1. **Dark-launch** classifier (log-only) for 1 week  
2. Enable retries for `web_retrieval` task type, 1 tenant at a time  
3. Broaden to all `retryable_transient` tasks after stable success rate  

## Risks  
- **Masking bugs**: Conservative classifier rules + "retried N times" dashboard signal  
- **Resource surge**: Per-tenant retry budgets + global circuit breaker  
- **UI clarity**: "Retried run" flag in task history
