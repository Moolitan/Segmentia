# SegKV 研究笔记(四):内部漂移是否传导至输出——端到端可行性验证

## 导读

本笔记承接前三篇:笔记一至三测量的均为**模型内部**中间指标(K、V、激活的相似度),
确立了"位置可修、深层 V 漂移宽且深、选择性重算空间有限"。本篇回到最终裁决性的
问题:**内部漂移到底会不会改变模型实际写出的内容?改变成什么样?** 这是 SegKV
可行性的端到端验证。术语在第一次出现处给出直观解释。

**摘要.** 我们在位置误差已修复(免训练重旋转)的条件下执行真实 KV 注入复用,
令模型完整生成思考过程与最终产物,与完整重算的真值逐点对比。6 个任务、24 个
复用点的结果呈**双峰分布**:14/24 的产物与真值几乎一致(语义相似度 >0.99,部分
逐字相同),6/24 真实分叉(最低 0.52)。逐点检视原文显示:**全部分叉点均非文本
劣化,而是 agent 在多解决策点选择了另一条同样合理的下一步动作**;分叉与否的
决定因素是复用点处的**决策分叉度**,而非 skill 身份或任务属性。结论:**位置修复
后的直接复用在输出层面大体无损,SegKV 的可行性在端到端层面成立**。本系列的
表征阶段(characterization)就此收束;研究自此收敛到设计阶段——为本场景构建
V 修复(跨注意力恢复)机制,见 §6。

## 1. 实验方法

与前三篇的根本区别:不再比较内部中间量,而是**让模型真实复用 KV、真实生成全部
回答与产物,再比较两份生成文本**。三个关键设计:

**(1) 真实 KV 注入,且仅注入——位置先修复。** 真实 agent 每轮把 skill(作为
工具结果)追加到对话末尾并紧随其后生成。我们在 skill 被加载的轮次上测量:

- **源(occ1)**:skill 首次加载的轮次。仅 prefill,保存该段全部层的真实 K、V。
- **复用点(occ_k, k≥2)**:skill 后续每次重新加载的轮次。将该段 K/V 替换为
  occ1 缓存,其余上下文照常重算,随后生成。

注入发生在 `DynamicCache.update()` 内(位置编码之后、注意力计算之前)。occ1 的
K 携带 occ1 位置的旋转,直接注入会引入位置误差——而笔记一已证明该误差可免训练
精确修复。故注入前按位置差 `delta = occ_k 起点 − occ1 起点` 将 occ1 的 K
**重旋转**至 occ_k 位置(与真实系统 `rope.py` 的实现一致);V 不携带位置,原样
注入。由此测得的是**位置已修、仅余内容误差**的真实 SegKV 代价,而非"位置也错"
的裸复用。

> 重旋转正确性已独立校验:第 0 层 K 重旋转后相似度恢复 **1.000**(第 0 层只有
> 位置差、无内容差,精确恢复即证明位置数学无误);深层 K 由 ~0.65 升至
> 0.83–0.91,与笔记一、二的逐层数据吻合。

**(2) 生成长度覆盖完整产物。** Qwen3 先在 `<think>...</think>` 内思考,随后
输出真实产物(网页、代码、Slack 消息)。生成长度设为 2048 token 以确保越过
`</think>`;本轮 24 个复用点全部到达产物段。

**(3) 分段度量。** 将每份生成按 `</think>` 切分为**思考段**与**产物段**分别
评估。对两份真实生成文本沿三个维度比较:

| 指标 | 度量对象 | 数值越高 |
|---|---|---|
| 嵌入余弦(cos) | 语义接近度(末层隐状态均值夹角) | 语义越一致 |
| ROUGE-L | 句法骨架/语序 | 结构越一致 |
| BLEU-4 | 逐字措辞 | 用词越一致 |

## 3. 分叉点定性分析:非文本劣化,而是下一步动作换至另一合理分支

逐点检视 6 个分叉点的原文,模式高度一致:在 dist_to_gen=3 处,模型紧随生成的
通常是一个**工具调用决策**,复用将该决策推向**另一条同样合理的分支**:

| 复用点 | 真值版下一步 | 复用版下一步 |
|---|---|---|
| slack-gif-creator occ3 | `Read` 再读一个 skill 文件 | 直接 `Write` 最终 launch pack |
| web-artifacts-builder occ2 | `Write` 海报 markdown | `Bash` 运行打包脚本 |
| canvas-design occ2 | `Write` 海报 PNG | 输出散文式收尾总结 |

两条轨迹各自均合理,无一为"坏输出";产物 cos 被拉低仅因一侧是短工具调用、
另一侧是长内容,表面差异大。反之,下一步**唯一确定**的复用点(如 mcp-builder
occ3、web-artifacts-builder occ3)两版产物**逐字相同**(cos=1.0),复用零影响。

→ 决定"分叉与否"的因素不是 skill 身份,也不是任务属性,而是**复用点处下一步
动作的合理分支数(决策分叉度)**。分叉点几乎全部集中于
`launch_poster_page_pack` 这类"接下来写哪个文件、是否打包、是否再读 skill"
本就多解的场景。

## 4. 实验边界

本实验是**开环、干净历史、出现间相互隔离**的受控测量,边界须明确陈述以防结论
被过度外推:

- 每个 occ_k 运行在**真实录制 trace 的历史**上,该历史由真实 agent 在无复用
  条件下产生("干净");
- 每个 occ_k 与**其本地真值**(当场完整重算)对比;
- occ2 的复用结果不进入 occ3 的输入——各次出现相互隔离。

故本实验度量的是**单次复用在隔离条件下的影响**,是一个干净的下界/隔离量,
不等同于闭环系统的端到端行为:(1) 此处的单步"下一动作分叉"不等于最终产物
劣化——agent 沿不同分支继续运行可能殊途同归,单步分叉会高估伤害;(2) 真实系统
中复用产生的输出会进入后续历史,跨轮交互效应未被本实验覆盖。带真实 agent 回路
的闭环 rollout(复用 ON/OFF 各自跑完任务 + 任务级 LLM-judge 评产物)是系统级
评估的终极形态,留作系统原型完成后的整体评估,不阻塞当前的机制设计。

## 5. 结论:可行性成立

1. **位置修复后,直接复用在输出层面大体无损**:24 点中 14 点产物近乎一致
   (语义 >0.99),思考段全部"自由改写、语义稳定"。
2. **少数点改变 agent 的下一步动作**(6/24,产物 cos 最低 0.52),但全部为
   合理替代轨迹,非文本劣化。
3. **分叉与否由决策分叉度决定**,与 skill 身份、任务属性无关。
4. **端到端可行性由此确立**:免训练重旋转 + 直接复用构成 SegKV 的可用基线——
   多数单次复用无需任何修复。这同时回答了笔记三留下的传导问题:深层 V 漂移
   (内部 ~0.5)在多数情形下**不传导**为产物劣化;它的输出端表现集中在高分叉度
   决策点上。

## 6. 收敛:从可行性验证到修复机制设计

表征阶段(笔记一至四)就此收束,所得问题结构如下:

- **可行的基线**:免训练重旋转 + 直接复用,多数复用点输出无损(本篇);
- **残余的系统性误差**:深层 V 漂移(~0.5),其本质是**复用段对新前文的跨注意力
  缺失**(笔记一)。它在输出端多数情形不显化,但它是复用质量缺口的唯一根源,
  也是与完整重算之间始终存在的差距;
- **修复的结构约束**:漂移宽(全 token,笔记三)且深(深层,笔记二),
  token 级选择性重算失效,层维续算有效但节省有限。

本系列下一阶段与 CacheBlend、EPIC、CacheSlide 进入同一问题类——**为复用段恢复
跨注意力**——但本场景的表征证据决定了机制不能照搬:CacheBlend(重算 ~18%
token)与 CacheSlide 的 Weighted Correction Attention(第 1 层按 K 偏差选
top-26% token,逐层加权融合)均以"漂移集中于少数 token"为前提,该前提在本场景
被笔记三直接否定;CacheSlide 的 CCPE 还需按任务 LoRA 续训,放弃了免训练性质。
由证据导出,本场景的修复机制须满足两个设计要求:

1. **按层挑重算范围,不按 token 挑**:只重算深层、浅层照用缓存是有效的
   (笔记二:浅检查点续算回收 86%);只重算一部分 token 则无效(笔记三:
   每个 token 都漂,恢复曲线无拐点);
2. **全程免训练**(笔记一:位置误差已免训练解决,机制整体保持该性质方可即插
   即用)。

修复机制在输出端的实测见[笔记五](<(五)修好内部输出能跟着修好吗.md>)。
