# SegKV 研究笔记(四):内部坏了,输出会跟着坏吗?

## 这份文档怎么读

接着前三份走。前三份测的都是**模型内部**的中间数字(K、V、激活向量像不像);这一份回到
最要紧的问题:**这些内部变化,到底会不会改变模型实际写出来的输出?变成什么样?** 名词第一次
出现仍用大白话解释,建议顺着读。

先把结论放最前面:

> 把位置误差先修好(用笔记一的免训练重旋转),只留下内容误差,再让模型**真的把回答和产物
> 写完**,然后比"复用版"和"真值版"的产物——结果是**双峰的**:24 个复用点里 **14 个产物
> 几乎一模一样**(语义相似度 >0.99,有的逐字相同),**6 个真的分叉了**(相似度低到 0.52)。
> 但读原文会发现,这 6 个分叉**不是文字坏掉,而是 agent 选了一个不同(但同样合理)的
> 下一步动作**——比如真值版去"读另一个文件",复用版直接"写最终产物"。
>
> 不过上面这套测量是**隔离的(occ 间互不影响)**,而真实系统是**累积的**。补做的累积实验
> (4.1)显示:**误差会累积、不自愈**——一次上游复用就在下一次的 frontier 额外加 30–130%
> 偏移。所以单次复用大体无损,但"复用越多偏得越多"是真实风险;**复用到底伤不伤最终产物,
> 仍需闭环 rollout(4.2)定论**。

---

## 1. 怎么测:先修好位置,再让模型真的把产物写完

这一份和前三份最大的区别:不再比模型内部的中间数字,而是**让模型真的复用 KV、真的把回答
连同产物写出来,再比两份产物**。三个关键设计,逐条说清楚:

**(1) 真实复用 KV,而且只复用——位置先修好。** 真实 agent 每一轮把 skill(作为工具结果)
追加到对话末尾,紧接着在后面生成。我们在 skill **被加载的那一轮**测:

- **源(occ1)**:skill 第一次加载的那一轮,只做 prefill,把这段 token 的真实 K、V 存下来。
- **复用点(occ_k, k≥2)**:skill 后续每次重新加载的那一轮,把它那段的 K/V 换成 occ1 的,
  其余上下文照常重算,再生成。

注入发生在 `DynamicCache.update()` 里(注意力计算前、位置编码之后)。**关键:occ1 的 K
带的是 occ1 位置的旋转,直接塞到位置更靠后的 occ_k 会带来位置误差——而笔记一已经证明这
误差能用免训练的重旋转精确补掉。所以注入前,我们把 occ1 的 K 按位置差
`delta = occ_k起点 − occ1起点` 重新旋转到 occ_k 的位置**(和真实系统 `rope.py` 的做法一致);
V 不带位置,原样注入。这样测出来的才是真正 SegKV 的代价(位置已修、只剩内容误差),
而不是"位置也错"的裸复用。

> 重旋转的正确性已单独验证:第 0 层 K 重旋转后相似度回到 **1.000**(第 0 层只有位置差、
> 没有内容差,补平即证明位置数学精确),深层 K 从 ~0.65 提到 ~0.83–0.91,与笔记一二的
> 逐层数字吻合。

**(2) 生成够长,走完思考、写到产物。** Qwen3 回答前会先在 `<think>...</think>` 里想一段,
想完才写真正的东西(网页、代码、Slack 消息)。所以生成长度给到 2048 token,确保走出
`</think>`。本轮 **24 个点全部到达了产物段**。

**(3) 分段衡量。** 把每份生成按 `</think>` 切成**思考段**和**产物段**,分别比。比的是两份
**真生成文本**,三个角度:

| 指标 | 看什么 | 越高 |
|---|---|---|
| 嵌入余弦(cos) | 两份**意思**像不像(模型末层隐状态均值夹角) | 语义越接近 |
| ROUGE-L | 句子骨架/语序像不像 | 结构越接近 |
| BLEU-4 | 逐字措辞像不像 | 用词越接近 |

## 2. 结果

6 个任务、24 个复用点(全部贴着生成位置,dist_to_gen=3,且全部到达产物段)。

![复用对输出的影响](../../../../results/05_context_segment_agent_kv/plot/perturn_impact.png)

**左图怎么读**:每根柱是一个复用点的**产物段**语义相似度,按任务分组。绿(>0.99)是几乎
无损,灰(0.95–0.99)是轻微,红(<0.95)是真分叉。一眼看到:大多数贴着顶,少数几个
(canvas occ2、web-artif occ2/occ3、theme occ2、gif-crt occ3)掉下来。

**右图怎么读**:横轴产物逐字相似度(BLEU-4)、纵轴产物语义相似度(cos)。绝大多数点挤在
右上(语义高);左下那条尾巴是分叉点,它们 BLEU-4≈0 **不是因为文字乱掉,而是因为复用版
选了不同的工具/长度**(下一节展开)。

分段统计:

| 段 | cos 中位 | cos 最低 | BLEU-4 中位 | 解读 |
|---|---|---|---|---|
| 思考段 | 0.995 | 0.978 | 0.25 | 措辞自由改写,但语义始终稳定 |
| **产物段** | **0.992** | **0.516** | 0.42 | **14/24 几乎无损(>0.99),6/24 分叉(<0.95)** |

## 3. 那 6 个分叉点是什么:不是文字坏掉,是"下一步动作"被掀到另一条岔路

逐个读原文,规律高度一致。在 dist_to_gen=3 时,模型紧接着吐出的往往是一个**工具调用
决策**,而复用 KV 会把这个决策推到**另一条同样合理的岔路**:

| 复用点 | 真值版的下一步 | 复用版的下一步 |
|---|---|---|
| slack-gif-creator occ3 | `Read` 再读一个 skill 文件 | 直接 `Write` 最终 launch pack |
| web-artifacts-builder occ2 | `Write` 海报 markdown | `Bash` 跑打包脚本 |
| canvas-design occ2 | `Write` 海报 PNG | 写一段散文式收尾总结 |

两条轨迹**各自都合理**,没有一个是"坏输出"。产物 cos 被拉低,只是因为一个是短工具调用、
另一个是长内容,表面差异大。反过来,下一步**唯一明确**的点(如 mcp-builder occ3、
web-artifacts-builder occ3)两版产物**逐字相同**(cos=1.0)——复用零影响。

→ 真正决定"分不分叉"的,不是 skill 是哪个、也不是笔记里曾猜的"任务核心度",而是
**复用点处下一步动作本身有多少条合理岔路(决策分叉度)**。分叉点几乎都集中在
`launch_poster_page_pack` 这类"接下来写哪个文件、要不要打包、要不要再读 skill"本就
多解的场景。

## 4. 本实验的边界(scope),累积实验,以及最终的闭环验证

**这个实验是"开环、干净历史、occ 间互不影响"的受控测量。** 必须把它的边界说死,否则容易
把结论用过头:

- 每个 occ_k 都跑在**真实录制下来的那条 trace 的历史**上——而这条历史是真实 agent 在
  **没有任何复用**下产生的,是"干净"的;
- 每个 occ_k 各自和**自己当地的 truth**(当场全新重算)比;
- **occ2 的复用结果不会流进 occ3 的输入**——三次出现彼此隔离。

所以本实验测的是**每一次复用、在隔离条件下、单步的影响**——它是一个干净的**下界/隔离量**,
**不代表真实闭环系统的行为**。真实系统有两件本实验看不到的事,对应两条限制:

**限制一(单步 vs 最终产物)**:上面测的是**单步的"下一动作分叉",不是最终产物质量**。复用
版选了不同的下一步,**不等于**最终产物更差——agent 接着往下跑,很可能殊途同归到一样好的
结果。单步分叉会**高估**伤害。

**限制二(开环隔离 vs 累积闭环)**:真实系统是**累积**的。occ2 复用 occ1 后,它 decode 出的
(可能略偏的)输出会**变成对话历史**;等 occ3 出现时,它所处的上下文里已经含有那段在复用下
产生的 occ2 输出,然后又复用一次。误差/偏移可能**一次次叠加**。本实验把 occ 隔离开,
**完全看不到这种累积**。累积通过两条通道发生:

1. **历史污染通道**:复用后输出略偏 → 进入历史 → 后面每一轮都在略偏的历史上条件生成
   (这正是 V 没修干净的下游后果);
2. **轨迹分叉通道**:一旦某次复用把下一步动作掀到另一条岔路(上面那 6/24),后续就是
   **完全不同的轨迹**,录制的 trace(无复用轨迹)不再适用。

> **这两条限制指向的核心科学问题**:跨位置 KV 复用的误差,在长 agent 轨迹上到底是
> **累积(雪球)**还是**自愈(每轮真实新上下文把小偏差冲掉)**?无论答案是哪个都有价值——
> 雪球 → 必须周期性 re-ground/刷新缓存(刷新频率本身是个系统策略);自愈 → 对激进复用是
> 更强的许可证。

### 4.1 实验甲(累积、agent-free):已做,误差会累积

测**限制二的历史污染通道**,不跑真 agent。做法:对每个 occ_k,在它真实请求的 frontier 上
teacher-force **同一条 fresh 参考续写**(轨迹held住,排除分叉通道),比三种条件相对 fresh 的
预测偏移:

- **fresh**:不注入(参考);
- **隔离**:只在 occ_k 注入 canonical KV(= 第 1–3 节那套);
- **累积**:在 occ2..occ_k **全部**注入(真实系统到这一轮会做的每一次上游复用)。

`累积 − 隔离` = 纯粹由**上游复用**贡献的额外偏移。

![累积影响](../../../../results/05_context_segment_agent_kv/plot/cumulative_impact.png)

**结果(图)**:occ2(无上游)隔离==累积、accum 精确为 0(12/12,内置正确性校验);occ3
(1 个上游复用)**12 个点里 10 个 accum 为正**,而且相对幅度可观——一次上游复用就在 occ3
frontier 上**额外加了 30–130%** 的偏移(canvas +134%、internal-comms +76%、web-artif +60%……),
只有 1 个点轻微为负。

> **结论:误差会累积,不是自愈。** doc 四第 1–3 节的隔离测量是个**下界**——真实闭环系统因为
> 上游复用污染历史,偏得更多。仅一步上游就已把偏移在最坏情况翻倍以上。

**诚实限制**:本 trace 每个 skill 只出现 ≤3 次,所以上游数最多 1(occ3 带 occ2)。这给出了
**累积的第一个数据点(确实在加,不自愈)**,但还看不到长程曲线是**线性增长、饱和、还是
最终失控**——要看清需要复发 4 次以上的 skill。

### 4.2 实验乙(闭环、最贵):仍是下一步

测**限制一 + 轨迹分叉通道**。用真实 agent harness(`real_system/`,带 vLLM ContextSegmentKV),
复用 ON vs OFF 各自把任务跑到底,用**任务级 LLM-judge**(完整性、格式、事实一致)比**最终
产物**是否系统性变差。这是把本笔记观察变成结论的最终 ground truth,但需要真 agent loop +
真工具执行。

## 5. 结论

1. **位置修好后,复用对产物大体无损**:24 个点里 14 个产物几乎一模一样(语义 >0.99),
   思考段则永远是"自由改写、语义稳定"。
2. **少数点会改变 agent 的下一步动作**(6/24,产物 cos 低到 0.52),但读原文都是
   **合理的不同轨迹**,不是文字崩坏。
3. **决定分不分叉的是"决策分叉度",不是 skill 身份或任务核心度**——后者(曾经的猜测)
   被本轮数据否定。
4. **隔离测量是下界:误差会累积**(实验甲,4.1)。一次上游复用就在 occ3 frontier 额外加
   30–130% 偏移(10/12 为正),说明真实闭环系统比隔离测量偏得更多,**不自愈**。
5. **仍不能下"复用伤最终产物"的结论**:累积是在 teacher-force 住轨迹下测的预测偏移,还要
   **闭环 rollout + 任务级质量裁判**(实验乙)才能定论最终产物质量。

---

## 6. 这对设计的意义

> **基本盘成立:位置修好后,单次复用在产物层面大体无损。** 这支持 SegKV
> "免训练重旋转 + 直接复用"——大多数**单次**复用不需要额外修复。

> **但"几乎免费"要打个折:误差会累积。** 实验甲已证上游复用会把偏移叠上去(不自愈),
> 所以"复用次数越多、偏得越多"是真实风险。这把设计从"修不修单次复用"推向一个**系统问题**:
> **多久 re-ground / 刷新一次 canonical 缓存**,把累积控制在阈值内——刷新频率本身就是个
> 系统策略,且其触发可落在**累积速率 + 决策分叉度**上(而非曾经设想的 skill 核心度)。
> 是否真到了伤害最终产物的程度,仍需闭环 rollout(实验乙)定论。
