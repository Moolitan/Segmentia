# SegKV 研究笔记(三):内容误差的 token 级分布——选择性重算的前提检验

## 导读

本笔记承接[笔记二](<(二)坏掉的V能不能修.md>):深层 V 可由"残差流检查点 +
深层续算"免训练修复,但按层维度的节省上限仅 10–30%。要进一步省,自然的方向是
引入 token 维度——**只重算漂移最严重的少数 token**。该方向成立的前提是漂移在
token 维上是**集中分布**的;本篇实测这一前提。术语在第一次出现处给出直观解释。

**摘要.** 我们在 Qwen3-14B 真实 agent 对话上逐 token 测量复用 skill 段的 V 漂移
分布。结果:漂移**几乎覆盖每一个 token**——第 20 层 97% 的 token 相似度低于 0.7,
全段无一 token 高于 0.9;"重算最坏 X% token"的恢复曲线呈线性、无拐点,不存在
"重算一小撮即大幅恢复"的捷径。结合笔记二的层维结论,本场景的内容误差是
**"宽(全 token)× 深(深层)"**的,选择性重算的可省空间约 30%,质量仍非满分。
该负结果具有定位价值:CacheBlend(重算 ~18% token)、EPIC(重算每块边界 64
token)、CacheSlide(WCA 重算 top-26% token)等现有高效复用方法的共同前提——
"漂移集中于少数 token"——**在本场景不成立**。这一场景差异是 SegKV 与上述工作
的根本分界,并把问题推向输出级验证(笔记四)。

---

## 1. 动机:选择性重算的前提

本系列场景:agent 反复加载同一段 skill 文本,SegKV 跨出现复用其 KV 缓存。
笔记一、二已确立:

- 位置误差已由免训练重旋转精确修复,非瓶颈;
- 内容误差表现为深层 V 漂移(余弦相似度 ~0.5,1.0 为无损);
- 修复机制(检查点 + 续算)成立,但按层节省上限 10–30%。

现有工作普遍采用 **token 级选择性重算**降低修复开销:CacheBlend 在浅层比较后
重算偏差最大的 ~18% token;EPIC 重算每个缓存块的首尾各 32 个 token;CacheSlide
的 Weighted Correction Attention 在第 1 层按 K 偏差选 top-26% token 逐层重算并
与缓存加权融合。这些机制的共同前提是:

> **漂移集中于少数 token——重算那一小撮,整段质量即可恢复。**

- 若漂移**集中**(如仅十余 token 坏),选择性重算高效成立;
- 若漂移**弥散**(几乎每个 token 都坏),则必须近乎全量重算,token 维选择失效。

本篇直接测量该分布。

---

## 2. 实验设计

采用 Qwen3-14B 与真实 agent 对话(token 序列与前序实验完全一致并经校验)。
取真实 skill `internal-comms`(338 token),其在对话中出现两次、前文不同。
对**每一个 token** 计算"复用 occ1 的 V"与"occ2 处完整重算真值"的余弦相似度,
考察分布形态(实现见 `token_drift_concentration.py`)。

---

## 3. 结果:漂移弥散于几乎全部 token

### 3.1 分布统计

| 深层 | 漂移 token(<0.7)占比 | 完好 token(>0.9)占比 | 全段最佳 token |
|---|---|---|---|
| L20 | 97% | 0% | 0.74 |
| L30 | 60% | 0% | 0.90 |
| L39 | 91% | 0% | 0.85 |

**不存在"完好 token"**:全段最佳者也未达 0.9。漂移是普遍的。

### 3.2 选择性重算的恢复曲线

更直接的判据:"只重算最坏的 X% token,段平均相似度恢复到多少"。若漂移集中,
曲线应在小 X 处陡升;若弥散,只能线性爬升。实测为后者(L39):

| 重算最坏 token 比例 | 段平均 V 相似度 |
|---|---|
| 0%(全复用) | 0.51 |
| 10% | 0.58 |
| 20% | 0.64 |
| 30% | 0.70 |
| 50% | 0.81 |

每多重算 10% 仅线性回收一小段,**无拐点**——这是漂移均匀弥散的直接标志。
按 CacheBlend 的 18% 预算,段平均仅恢复至 ~0.63;按 CacheSlide 的 26% 预算,
约 ~0.68——均远未达可用区间。

### 3.3 词性细节:虚词漂移最重

漂移最严重的 token 几乎全为**虚词与标点**(" the"、逗号、换行、反引号、斜杠);
最轻的为**实词与专名**(" Incident"、" Status"、" Project"、"internal")。
机理自洽:虚词自身语义稀薄,其表示几乎完全由上下文决定,前文一换即整体改写;
实词自带语义锚点,漂移较轻。但需强调:**最轻的实词也仅 0.74–0.9,同样未能幸免**
——词性差异改变的是漂移程度,不改变"普遍漂移"的结论。

## 4. 含义:宽 × 深,选择性重算空间有限;场景分界确立

与笔记二合并:

- **层维**(笔记二):误差在深层,修复必须重算几乎全部深层,仅可免去浅层
  10–30%;
- **token 维**(本篇):误差弥散于几乎全部 token,按 token 挑选失效。

两维相乘:恢复质量需重算约"全 token × 深层" ≈ **整段计算量的 ~70%**。即
"靠选择性重算把修复做便宜"在本场景上限约省 30%,且质量仍非满分。

该负结果的定位价值在于场景分界:

> CacheBlend / EPIC / CacheSlide 的 token 级选择性重算,其有效性根植于各自场景
> (RAG 多段拼接、块边界效应、相对位置保持的 RPDC)中漂移的**集中性**。本场景
> ——**同一段 skill 被整体搬入一段完全不同的对话**——漂移宽且深,集中性前提
> 直接失效。这是 SegKV 的问题结构与上述工作的根本不同,也意味着本场景的修复
> 机制不能照搬 token 级选择,需另行设计。

## 5. 遗留问题:内部指标到输出质量的传导

至此全部测量基于 V 的余弦相似度——一个**内部中间指标**。它衡量模型内部表示的
偏差,**不直接等于生成文本的偏差**。存在两种可能:

- V 相似度 0.5 但实际生成几乎不变 → 内部漂移在工程上**不重要**,直接复用即可,
  修复全程可省;
- 生成确实劣化 → 我们面对一个"宽、深、修复昂贵"的硬问题。

二者决定 SegKV 的整体技术路线,必须在内部指标之外**直接测量输出质量**。这是
[笔记四](<(四)内部坏了输出会坏吗.md>)的任务。

(普遍性说明:本篇结果来自 `internal-comms` 单一 skill 的相邻一对出现;分布
形态清晰,但跨 skill 的普遍性在笔记四的 6 任务 × 24 复用点实验中得到间接覆盖。)
