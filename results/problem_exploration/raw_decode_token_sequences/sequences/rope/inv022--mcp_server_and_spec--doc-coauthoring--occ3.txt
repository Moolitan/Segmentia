# Final MCP Server Spec for Issue Tracker

## Concise Spec
**Tools:**
- `issue_query(id?, status?, assignee?, label?, updated_since?, limit<=100, cursor?)` → `{items, next_cursor, has_more}`
- `issue_create(title, body, labels?, assignee?)` → issue object
- `issue_comment_add(issue_id, body)` → comment object

**Behaviors:**
- `limit` clamped to 100 server-side with warning field
- All list responses include `next_cursor` (opaque) and `has_more` at top level
- 4xx errors: field-level validation messages + "fix and retry" instruction
- 5xx errors: retryable with `attempt_remaining` hint
- Auth: out-of-scope (treat API as trusted local)

#️ Top 3 Design Decisions

1. **Pagination Safety**  
   `limit<=100` cap prevents runaway context loads while `next_cursor` (opaque) ensures clients can paginate without parsing tokens.

2. **Error Guidance**  
   4xx errors explicitly instruct agents to "fix and retry" rather than loop, preventing deadlocks in agent workflows.

3. **Reader-First Design**  
   All tool responses include `structuredContent` and avoid free-text explanations, ensuring LLMs can parse outputs programmatically without context bleed.<|im_end|>
