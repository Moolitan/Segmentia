# SegKV 复用误差分解报告:位置那一半 vs 内容那一半

> 本报告回答一个问题:把一个 skill 的 KV cache 缓存下来、在对话很后面的位置复用,
> 误差到底来自哪里?结论是**两半**:一半是"位置",一半是"内容"。位置那半已被
> 免训练的 RoPE re-rotation 解决;内容那半(尤其 value、尤其深层)是真正的硬骨头。
> 所有数字都来自实测,不是推理。模型:Qwen3-14B(40 层,训练上下文 40960)。

---

## 0. 名词定义(先把话说清楚)

为避免歧义,先定义后文用到的每个词。

- **Transformer 的"层 (layer)"**:Qwen3-14B 有 40 层,数据从第 0 层流到第 39 层,
  逐层加工。

- **隐状态 `h_l`(hidden state)**:一个 token 在**第 l 层的内部表示**,可以理解为
  "模型读到这里、走到第 l 层时,对这个 token 的当前理解"。它是一个向量。
  - 第 0 层的 `h_0` ≈ 这个词本身的 embedding(只认字,不看上下文)。
  - 越往深层,`h_l` 越融合了"前文",越是"结合上下文后这个词的意思"。

- **注意力 (attention)**:每一层里,一个 token 会去"看"它**前面所有 token**
  (因果注意力),按相关度加权,把信息汇聚进自己的 `h_l`。这就是上下文进入
  `h_l` 的唯一通道。

- **K 和 V(Key / Value)**:每一层里,由 `h_l` 线性投影出来的两个向量:
  - `K = W_k · h_l`,**Key**,管"寻址/匹配"——别的 token 用它来判断"要不要看我"。
  - `V = W_v · h_l`,**Value**,管"内容载荷"——一旦被看上,真正传递出去的内容。
  - 关键:**K 和 V 来自同一个 `h_l`**。`h_l` 一变,两者都会变。

- **KV cache**:把每个 token 每一层的 K、V 存下来,后续 token 算注意力时直接读,
  不用重算。这就是"复用"的对象。

- **位置编码 / RoPE**:模型靠它知道"每个 token 在第几位"。RoPE 把"第几位"编码成
  对 K(和 query)施加的一个**旋转角度**。RoPE 是**相对**的:两个 token 的注意力
  只取决于它们的**位置之差**。

- **re-rotation(本项目 `rope.py` 做的事)**:复用时,skill 的缓存 K 是在"旧位置"
  算的;把它的旋转角度按"新位置 − 旧位置"重新拧一下,使它的位置相位对齐到新位置。
  **只动 K,不动 V**(V 不带位置)。

- **skill 段 / occurrence (occ)**:一个可复用的技能文本块(如 `internal-comms`)。
  它在一段 agent 对话里会**多次出现**;第 1 次叫 occ1,第 2 次 occ2……每次出现时,
  它**前面的对话内容都不同**,绝对位置也越来越靠后。

- **CKSim**:衡量"复用得到的 KV"和"真重算得到的 KV"有多像的余弦相似度。
  1.0 = 完全一样(无损);越低 = 漂移越大。本报告对 K、V 分开算、逐层算。
  - 配套指标 `|Δ|/|·|`(drift norm):`‖重算 − 复用‖ / ‖重算‖`。≈0 完全一致;
    ≈1.0 表示两个向量**接近正交(~90°)**,基本不可用。

- **复现代码**:
  - CKSim 主数据:`replay/trace_reuse_cksim.py`(三阶段:recompute / reuse / summarize)。
  - 本报告的 K-vs-V 结构分析:`replay/kv_drift_analysis.py`(只读已有 .pt,不碰 vLLM)。

---

## 1. 问题:复用误差从哪来?

把 skill 的 KV 缓存一次,在 occ2/occ3 复用,和"在 occ2/occ3 真重算"比,有差距。
这个差距可以拆成两个互相独立的来源:

- **(甲)位置**:skill 复用时落在对话很后面,绝对位置变了。
- **(乙)内容**:skill 前面的对话变了(occ1 前是 P1,occ2 前是 P2≠P1),
  而缓存的 KV 是"当初对着 P1 算的"。

下面分别量化这两半。

---

## 2. Step 1:位置那一半——已被 re-rotation 免训练解决

### 2.1 为什么 re-rotation 对位置是精确的

vLLM 在每层把 RoPE 应用到 K 后才写进 cache,所以缓存的第 l 层 key 是
`K_l = R(旧位置) · (W_k · h_l)`。re-rotation 乘上 `R(新位置 − 旧位置)`,得到
`R(新位置) · (W_k · h_l)`——**正好是把这段 key 摆到新位置应得的结果**,逐层都成立。
所以:**只要 `h_l` 不变,re-rotation 在所有层都是精确的。**

### 2.2 外推风险已排除

re-rotation 唯一可能在纯位置上翻车的地方,是新位置**超出模型训练长度**(RoPE 高频
区行为异常)。实测:

| 项 | 值 |
|---|---|
| Qwen3-14B 训练上下文上限 | **40960** |
| `rope_scaling` | None(未开 YaRN/NTK) |
| trace 中 skill 复用的最大目标位置 | **24666**(约 60% 上限) |

→ 所有复用位置都在训练窗口内,**无外推问题**。

### 2.3 实测证据:re-rotation 只补 K、不动 V

数据集里有一个"**不做 re-rotation**"的对照组(`reuse-no-rope`)。8 个 case 聚合:

| | key CKSim | value CKSim |
|---|---|---|
| **有** re-rotation | **0.900** | 0.743 |
| **无** re-rotation | **0.636** | 0.743 |

- re-rotation 把 key 从 **0.636 → 0.900**——这就是它补回的"位置那一半"。
- value **几乎完全不变(0.7432 vs 0.7433)**——因为 value 不带位置,旋转碰不到它。

### 2.4 Step 1 结论

> **位置那一半已经被免训练的 re-rotation 解决;残留(key 仍 < 1.0、以及全部 value
> 漂移)与位置无关,属于内容那一半。**
>
> 对标意义:竞品 **CacheSlide(FAST'26)** 花了一整套**需要重训**的 CCPE(CoPE 位置
> 编码)去打位置偏移;而本数据证明,在 ≤40k 的真实 agent 场景里,**免训练的
> re-rotation 已把位置解干净**。CacheSlide 之所以认为位置是大问题,很可能因为它的
> RoPE 基线根本没做 re-rotation(对应我们 0.636 那一行)。

---

## 3. Step 2:内容那一半——真正的硬骨头

### 3.1 机制:漂移 = skill 回头 attend 到不同的前文

skill 段内每个 token,在注意力里既看段内,也看**前面的对话**。段内结构 occ1/occ2
完全一样;唯一变量是前文 P1≠P2。于是:

- **第 0 层**:`h_0` 只是 embedding,不看上下文 → K、V 与前文无关 → CKSim = 1.0000。
- **越深越漂**:每过一层就多混入一次"对不同前文的注意力",误差**逐层累积**。

### 3.2 核心发现:V 比 K 漂得多,且是结构性的

`kv_drift_analysis.py` 实测(internal-comms,T=338;doc-coauthoring,T=3313,结论一致):

| 层 | Kcos | Vcos | \|ΔK\|/K | \|ΔV\|/V | K单维占能量 | V单维占能量 | 去K前2%维后Kcos |
|---|---|---|---|---|---|---|---|
| 0  | 1.000 | 1.000 | 0.00 | 0.00 | 94% | 4% | 1.000 |
| 15 | 0.928 | 0.776 | 0.37 | 0.68 | 34% | 2.4% | 0.900 |
| 20 | 0.826 | **0.489** | 0.59 | **1.03** | 12% | 2.5% | 0.80 |
| 24 | 0.768 | **0.480** | 0.68 | **1.04** | 5.6% | 2.0% | 0.77 |
| 39 | 0.908 | **0.515** | 0.43 | **0.91** | 56% | 3.2% | 0.80 |

三个读法:

**① 深层 V 接近不可复用。** `|ΔV|/V ≈ 0.9~1.0` 意味着深层复用的 V 与真值**接近正交
(~90°)**,Vcos 掉到 ~0.5;同层 K 还有 0.82~0.91。

**② 为什么 K 抗漂、V 不抗?数据给出物理解释:**
- **K 带 "massive activation"**:单个特征维就占 K 总能量的 12%~94%(深层 38-39 回到
  47-56%)。这种"少数大而稳、与前文基本无关"的方向,把 K 的余弦撑住。
- **V 没有**:能量均匀摊开(单维仅 2~4%),全是随上下文变的内容。
- **验证**:把 K 最大的 2% 维去掉,Kcos 从 0.908 只掉到 0.796,**仍远高于 V 的 0.5**
  → K>V 不只是 massive activation 撑的,更本质是:
  > **K = 寻址/路由信息(我是什么)→ 跨上下文稳定 → 可复用;
  > V = 按上下文加工的内容载荷 → 上下文一变就变 → 不可复用。**

**③ 与 CacheSlide 矛盾。** 它声称"V 相似度跟随 K"。本数据显示深层 **K≈0.9、V≈0.5
剧烈分叉**,且在 338 与 3313 两个量级、随深度单调、去掉大维后仍成立——**可复现、
非伪影**。这是 SegKV 可正面立的 characterization。

(附:漂移在中深层 20-24 最严重,极深层 28-39 的 K 部分回弹、V 仍低——U 形,留作细节。)

### 3.3 Step 2 必须诚实交代的系统张力(Step 3 的命门)

K 和 V 都是**同一个 `h_l`** 的投影。因此:

- 想要"真 V",**必须重算 `h_l`**(那次贵的注意力);
- `h_l` 一旦算出,顺手算 K 几乎免费;
- ⟹ **"复用 K、只重算 V"省不了计算**——这是个陷阱,必须正视。

所以省算力的真正杠杆只能是**减少 `h_l` 的生产工作量**,有两条候选路线,留给 Step 3:
- **按 token 减**(CacheBlend 路线):只 forward 高漂移的少数 token。
- **按层深减 + 残差检查点**:浅层 KV 近无损直接复用,只从第 N 层往后重算;代价是要
  额外缓存段在第 N 层的残差隐状态 `h_N`,且深层重算时 attend 真实前文。此路线不在
  主流 token-selective 范式内,可能是 SegKV 的设计点(待 Step 3 评估其正确性与省算力)。

---

## 4. 总结(已锁定)

1. **位置那一半**:re-rotation 对位置数学精确;所有复用位置在 40960 训练窗口内,无
   外推;实测 key 0.636→0.900、value 不变。**免训练解决,位置不是瓶颈。**
2. **内容那一半**:漂移源于跨段注意力到不同前文,逐层累积;**V 远比 K 漂(深层
   V≈0.5 近正交,K≈0.9),结构性、可复现**;物理因:K 稳定寻址(带 massive
   activation),V 为上下文相关载荷。**与 CacheSlide 的"V 跟随 K"矛盾,是核心 claim。**
3. **系统张力**:K/V 共享 `h_l` ⟹ 组件级"只重算 V"不省算力;省算力须减少 `h_l`
   生产(按 token 或 按层深+残差检查点)。这是 Step 3 要解决的核心设计问题。
