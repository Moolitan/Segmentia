# SegKV 研究笔记(五):修 V,该按 token 挑,还是按层深?

## 这份文档怎么读

接着前面几份走。名词第一次出现仍用大白话解释,建议顺着读。

先把结论放最前面:

> 要修复复用带来的误差,有两条思路:**按 token 挑**(只重算坏得最厉害的几个字,别人
> CacheBlend/CacheSlide 走这条)和**按层深修**(浅层直接复用,只从某一层往下重算所有字)。
> 这份笔记把两条放在**同一把尺**上公平比较。结论是:**按 token 挑天花板就低,到不了
> 高质量——即使用"上帝视角"挑出真正最坏的字也一样;只有按层深才能修到高保真,但代价
> 是要重算大部分层。** 原因是"邻居污染"(下面解释)。同时,**用便宜的浅层信号去挑该
> 修哪些字,也失败了。** 这两点合起来,把"按 token"这条路否决掉了。

---

## 1. 回顾:为什么要做这个比较

我们在做的事:AI agent 反复用到同一段固定文字(skill),把它的中间结果缓存复用、省时间。
复用会带来误差,主要在深层的 V(可以理解成"这个字要传出去的内容")。

前面发现:这个误差又宽(几乎每个字都坏)又深(越深越坏)。那要修它,到底该怎么修、
划不划算?之前笔记三用一条"理想化"的曲线粗看了一下,但那条曲线假设"被重算的字会变得
完全正确",不公平。这份笔记用真实测量,把几种修法放在同一把尺上比。

---

## 2. 做法:同一把尺

我们用一个统一的开关:对 skill 的每一个"(字 × 层)"格子,决定它是

- **复用**(冻结成第一次出现时的值,也就是带误差的),还是
- **重算**(让它正常计算,去看真实的前文和邻居)。

不同修法就是不同的开关图案:

- **全复用**:全部冻结(成本 0)。
- **按层深@N**:浅的 0~N 层冻结,N 层往下全部重算(这就是"中间存档"那条)。
- **按 token@X%**:挑 X% 的字,这些字在所有层都重算,其余冻结(别人那条)。
- **2D**:只重算"被挑中的字 且 在深层"的格子。
- **全重算**:全部重算(成本 100%,质量满分)。

**成本** = 重算的格子占比(就是花了多少算力);**质量** = skill 深层 V 与"全重算真值"的
相似度(1.0 = 无损)。两条路都是真实测量(都去看真实前文和邻居),公平。

---

## 3. 结果图

![质量-成本 Pareto](../../../../results/05_context_segment_agent_kv/plot/pareto_recompute.png)

**这张图怎么读**:横轴是花的算力(越右越贵),纵轴是修复质量(越高越好,1.0 无损)。
左下角的星是"全复用"(不花算力、质量 0.53),右上角的十字是"全重算"(满算力、满质量)。
每条线是一种修法。**一条线越靠左上越好**(花得少、修得好)。

一眼能看出来:

- **蓝线(按层深)** 是唯一能爬到高质量(0.8 以上)的,但要到那儿得花 ~68% 以上的算力。
- **红线/黄线(按 token,普通选 和 上帝视角选)和绿线(2D)** 全都压在下面(0.53~0.66),
  无论花多少都上不去。

---

## 4. 三个结论

**第一,按 token 挑天花板就低,不是"选不准"。** 我特地加了"上帝视角"——直接挑出**真正
深层最坏**的字来重算(黄线)。结果它**并不比普通挑法好**(50% 算力下 0.63 对 0.66)。
说明就算给你一个完美的选字器,按 token 也只能到 0.6 出头,够不着 0.8。

**第二,原因是"邻居污染"。** 因为误差是**宽**的(几乎每个字都坏),你重算某个字时,它要
参考的**邻居还是坏的**(被冻结了),所以修不干净。而按层深是把**所有字一起**从浅层往下
重算,大家参考的都是彼此重算后的值,才能连贯地修好。**所以"按层深"才对,不是因为它
便宜,而是因为宽误差必须把字一起重算。**

**第三,没有便宜的修复。** 要修到 0.8 以上,只有按层深、且要花 ~68% 以上的算力。低算力
区(50% 以下)所有修法都挤在 0.6~0.66,基本没用。

---

## 5. 顺带:便宜的"选字器"也失败了

我们试了用**浅层的偏差**(很便宜、不用全重算就能算)去预测"哪些字深层会坏"。结果它和
"真正深层最坏的字"几乎不重合(只有 0~7%)。也就是说,**浅层信号根本指示不了深层的
坏**。这跟结论一叠加,等于把"按 token"判了两次死刑:**既到不了高质量,又没法便宜地选。**

(注意:这是**字级**的预测器失败。我们设计里真正需要的是**skill 级**的预测器——"这一次
复用会不会伤到最终输出",那是另一回事,还没测。)

---

## 6. 这对设计意味着什么(一个前提下)

**前提**:本篇回答的是"**如果**要修 V,该怎么修"。是否真的需要修 V,是输出层面的问题——
笔记四发现位置修好后产物大体无损,所以"要不要修"目前悬而未决(待多步 rollout 定论)。
在"需要修"这个前提下,这张图给出明确答案:

- **中间地带(按 token、2D)没有好的性价比,放弃。**
- 真正有用的是两个端点:**全复用**(免费)和**按层深修**(贵,但能高保真)。
- 所以修 V 的轴应当是"**按层深**"(我们用公平实验否决了"按 token",还能解释为什么——
  邻居污染);**字级**的便宜选字器也已证失败(第 5 节)。

这让故事更强:即使将来确认需要修 V,我们也已**用公平实验证明了竞品的"按 token"路线在本
场景从机制上就行不通**。

---

## 7. 诚实说明(还不能盖棺)

- 只测了 internal-comms 一个 skill、一对相邻出现。"邻居污染"这个机制是通用的,但具体
  数值要在别的 skill(尤其分叉大的 web_artifact)上复核。
- 质量用的是"深层 V 相似度";最终还要连到真正的输出/任务质量。

## 9. 承接下一步

本篇给出"怎么修"的答案:按层深整段重算才能修好,且这本身就贵。但"**要不要修**"是更前置
的问题——笔记四发现位置修好后产物大体无损,少数复用只是让 agent 换了个同样合理的下一步
动作,还不能断定伤害最终产物。所以下一步**不是**急着落地修复触发信号,而是先做
**多步 rollout + 任务级质量裁判**(见笔记四第 4 节),确认复用到底伤不伤最终产物:

- 若**不伤**,本篇的"按层深修"在输出层面可能并不必要,SegKV 收紧成"免训练复用、几乎免费";
- 若**伤**,本篇的修法重新有用,而"该修哪些复用"的触发信号应从**决策分叉度**这一侧重找
  (笔记四的新发现),而非曾经设想的任务核心度。
