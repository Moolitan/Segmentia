# Final Launch Pack for Internal Rollout

## 1. Main Slack Announcement
:gear: *Retry-on-failure is now live in the experiment task dashboard.*

*What it does*
- Detects transient failures (timeouts, transient I/O, rate-limit signals) and retries within a bounded budget per task
- Records each retry attempt against the original task id so history stays linked
- Leaves non-retryable failures (logic bugs, validation errors) to surface immediately, unchanged

*Why now*
Manual reruns were dominating operator time for failure shapes that are deterministically recoverable. The classifier was dark-launched for a week and matched our prior manual triage on 94% of failed runs.

*What it doesn't do yet*
- It does not retry across worker restarts; that lands next
- A handful of task types are still excluded while we tune the classifier

## 2. Fallback Version (Short)
:arrow_forward: Retry-on-failure is now live in the experiment task dashboard. It handles transient failures automatically while preserving non-retryable errors. Some task types are excluded temporarily.
