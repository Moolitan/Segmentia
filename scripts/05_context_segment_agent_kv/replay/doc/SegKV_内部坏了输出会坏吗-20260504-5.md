# SegKV 研究笔记(四):内部坏了,输出会跟着坏吗?

## 这份文档怎么读

这是第四份笔记,接着前三份走。名词第一次出现还是用大白话解释,建议从上往下顺着读。

先把结论放最前面:

> 前面三份笔记一直在测**模型内部的中间数字**(K、V、激活向量像不像),发现复用后深层
> 的"内容向量" V 坏得厉害(相似度只剩 0.5 左右)。但那是**间接指标**。这份笔记直接测
> **模型最后写出来的东西**——用了复用 vs 没用复用,回答差多少。结论是:
> **内部看起来很坏(V 相似度 0.5),但模型实际的输出几乎一样(行为有 96% 忠实)。**
> 也就是说,这个"坏"在工程上没那么要紧,**简单复用在 agent 的 skill 场景下,输出层面
> 是够用的。** 下面把这个结论怎么得出来的讲清楚,包括中间踩的一个指标坑。

---

## 1. 回顾:为什么要测这个

我们在做的事:一个 AI agent 会反复用到同一段固定文字(叫一个 "skill")。我们想把它的
中间计算结果缓存下来重复用,省掉重算的时间。

前几份笔记发现:复用时这段文字前面的对话变了,导致它在深层的 V(可以理解成"这个字
要传出去的内容")和"老实重算"的结果对不上,相似度只剩 0.5(满分 1.0),而且坏得又宽
(几乎每个字都坏)又深(越深越坏),修起来几乎要整段重算。

但这里有个一直没回答的关键问题:**这个 0.5 是模型内部的数字,它低,不代表模型最后
写出来的回答就坏。** 有可能内部很乱,但输出几乎不变。只有真去测输出,才知道这些"坏"
到底要不要紧。这就是这份笔记做的事。

---

## 2. 怎么测:模拟"复用",然后让模型真的写

我们用真正的 14B 模型 + 真实的 agent 对话。做法是让模型从完整的对话往下**生成一段
回答**,比较两种情况:

- **真值**:整段老实算(skill 用正确的内部状态)。
- **复用**:把重复出现的 skill 的内部状态**冻结成第一次出现时的**——这正是"复用、不
  重算"的真实效果(位置会自动按新位置处理,内容照搬第一次的)。然后让模型生成。

如果两种情况生成的回答几乎一样,说明复用够用;如果差很多,说明复用真会坏输出。

---

## 3. 第一次的坑:别被"逐字命中率"骗了

第一次我们简单地**逐字**对比两段生成,结果吓了一跳:只生成 64 个字时还有 94% 一样,
生成到 200-300 字时,逐字命中率掉到了 22-31%。

但**把两段文字读一遍,会发现它们说的几乎是同一件事**:都在过用户的三个要求(领导版、
内部群版、3 句话摘要)、都调用了 internal-comms 技能、都规划了同样的内容。只是用词不同。

这是**贪心解码的"蝴蝶效应"**:两条生成只要在某一步选了不同的词(这次是第 60 个字),
后面用词就会一路不同,但意思可以完全一样。所以:

> **"逐字命中率"是个会骗人的指标——它测的是用词一不一样,不是质量好不好。**

要下结论,得换一个不受蝴蝶效应影响的指标。

---

## 4. 用对的指标:沿同一条路,比每一步的"决策"

正确的办法叫 **teacher forcing**:**强行让两个模型沿着同一串文字走**(都喂真值那段
生成的文字),在每一个位置上,比较它们"预测下一个字"的结果差多少。因为喂的字一样,
不会分叉,这就干净地量出"行为差多少",而不是"用词差多少"。

比两样东西:

- **每个位置预测分布的差距**,用 KL 散度衡量(越接近 0 越像)。
- **同一个位置,两者预测的"最可能的下一个字"是不是同一个**(命中率)。

结果(200 个位置):

| 指标 | 结果 | 怎么理解 |
|---|---|---|
| 平均每字 KL | **0.067** | 非常小,两者预测分布几乎重合 |
| 同位置预测下一个字相同 | **96%** | 模型的实际决策有 96% 完全一致 |

所以真相是:**虽然内部 V 相似度只有 0.5,但模型实际的下一步行为有 96% 是一样的。**
之前那个 22% 是假象。

---

## 5. 结论:复用在输出层面够用,内部指标高估了问题

把上面合起来,用大白话说:

> **内部那些"漂移"严重夸大了真实影响。在真正要紧的地方(模型写出来的东西),不重新
> 训练模型的简单复用,有 96% 是忠实的。**

这给 SegKV 一个清晰、而且有点反直觉的故事线:

- 我们前几份笔记的 V 余弦分析(深层掉到 0.5),是**内部间接指标,它把问题放大了**。
- 在输出层面,简单复用几乎无损。
- 一个合理的解释:别人那些"必须重算"的方法,针对的是"一个字错就答错"的事实问答
  场景;而 agent 的 skill 多是**格式和风格的指导**,模型的输出对这种内部小扰动是
  **鲁棒**的。

如果这个结论在更多 skill 上也成立,SegKV 的卖点就可以是:**"免训练的简单复用,在
agent skill 场景下端到端够用,这是证据"**——而不必去做那套又宽又深、修起来很贵的重算。

---

## 6. 必须诚实说的(还不能盖棺定论)

1. **只有一个 skill、一个任务、200 个字的片段**。要换其它 skill 和任务,确认 96% 这个
   数稳不稳。
2. 96% 命中意味着**还有 4% 的字会翻**,而且个别位置的 KL 会突然冲很高(最高到 5.36)。
   在格式化的输出里,翻错一个关键的字(比如一个数字)可能就要紧——所以还需要**任务
   级的质量判断**(比如让另一个模型评判两份产物好不好),不能只看命中率。
3. 这次生成主要在模型的**内部推理**部分(虽然提到了用 skill),**还没测到模型真正
   "照着 skill 写出最终产物"那一段**——那里对 skill 的内容更敏感,值得单独看。
4. 这是在 HuggingFace 里**模拟**复用;最终要在真实的 vLLM 系统上复核一遍。

---

## 7. 下一步

最该做的,是把这个端到端测试**推广到更多 skill 和任务**,看"96% 忠实"这个结论稳不稳;
如果稳,再补一个**任务级质量评判**(产物好不好),以及在真实 vLLM 系统上复核。
