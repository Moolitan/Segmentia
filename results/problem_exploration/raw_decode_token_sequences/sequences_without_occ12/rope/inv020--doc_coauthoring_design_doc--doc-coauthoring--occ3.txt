# Final Design Doc: Automatic Retry for Failed Benchmark Tasks

## Summary
This document proposes a structured retry system for the experiment platform to reduce manual intervention for transient failures while avoiding masking real bugs.

## Key Components
1. **Failure Classification**  
   - `retryable_transient`: Timeouts, transient I/O errors  
   - `retryable_with_caution`: Rate-limit signals, backoff responses  
   - `non_retryable`: Logic errors, deterministic failures  

2. **Retry Policy**  
   - Max 3 retries for `retryable_transient` (exponential backoff: 30s → 60s → 120s → 5min cap)  
   - Max 1 retry for `retryable_with_caution` (30s delay)  
   - Logs: `retry_of`, `attempt_number`, `failure_class`, `delay_before_attempt`, `final_status_after_retries`  

3. **Rollout Plan**  
   - Phase 1: Dark-launch classifier (log-only) for 1 week  
   - Phase 2: Enable retries for `web_retrieval` task type, one tenant at a time  
   - Phase 3: Expand to all `retryable_transient` tasks after dashboard stability  

4. **Risks & Mitigations**  
   - **Masked bugs**: Conservative classifier rules + "retried N times" dashboard signal  
   - **Resource spikes**: Per-tenant retry budgets + global circuit breaker  
   - **Ambiguity**: Explicitly document classifier rules (TODO: finalize list)  

5. **Open Questions**  
   - How to handle retries across worker restarts?
